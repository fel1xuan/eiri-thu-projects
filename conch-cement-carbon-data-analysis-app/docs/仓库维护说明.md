# 目录与维护说明

本仓库保存稳定桌面软件的源码、正式资源和必要文档。目录整理不应改变 Python 导入关系、资源路径、配置结构或业务公式。

## 文件分类

| 类别 | 位置 | 维护方式 |
| --- | --- | --- |
| A. 正式运行源码 | `main.py`、`core/`、`ui/`、`utils/` | 保留原位，不为排版移动模块 |
| B. 软件资源 | `assets/logo.png`、`assets/app_icon.icns`、`assets/mindmaps/`、`config/default_config.json`、`config/version.json` | 保留资源路径及版本，配置模板不填私人路径 |
| C. 开发辅助脚本 | `scripts/render_xmind_mindmaps.py` | 可选的思维导图制作工具，依赖 Mac 字体，不是程序启动依赖 |
| D. 打包文件 | `packaging/`、`requirements-lock.txt` | 保留 spec 与已有环境记录；不提交构建输出 |
| E. 测试 | `tests/` | 使用临时目录和测试数据，不指向生产结果 |
| F. 文档 | `README.md`、`docs/`、`packaging/另一台Mac测试说明.md` | README 面向初次阅读者；平台说明保留在相关目录 |
| G. 临时与历史文件 | 本地历史验收报告、测试结果 JSON、`assets/archive/`、`assets/xmind_source/` | 已忽略，留在本地，不删除，也不混入正式资源 |
| H. 本机文件 | 虚拟环境、构建目录、App、用户配置、日志、本地启动脚本 | 已忽略，不提交；源码启动使用 README 中的命令 |

当前目录已具备明确分工，无需搬动源码。根目录仍可保留被 Git 忽略的本地文件，它们不会出现在 GitHub 文件列表中。

## 关键调用关系

- `main.py` 创建桌面应用和主窗口。
- `ui/main_window.py` 组织七个正式导航页面。
- 0号页面管理提取、自动检查和独立的人工审核；人工确认不是自动检查的别名。
- 一键运行页面通过后台 worker 调用现有 Pipeline，处理进度和结束状态。
- `core/pipeline.py` 编排后续业务入口；计算模块保留现有公式和输出规则。
- UI 和打包配置共同使用现有资源路径，正式 Logo 和思维导图 PNG 不应随意改名或搬动。
